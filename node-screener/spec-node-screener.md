# 불가결 노드 스크리너 기획서
Claude Code 개발용 · 2026-07-25 · v0.2 (루프 기반 개발 체계 도입)

---

## 0. 한 줄 정의
- 밸류체인을 그래프 데이터로 구축하고, 각 노드의 '불가결성'을 정량 스코어링해 **저평가된 병목 기업**을 찾는 1인용 리서치 도구

## 1. 목적·사용자·산출물
- 사용자: 1인 (본인). SaaS·배포 아님 — 리서치 자동화 도구
- 산출물 4종: ①체인 그래프 뷰 ②노드 스코어보드 ③2×2 매트릭스(불가결성×밸류에이션) ④노드 리포트(근거 링크 포함)
- 부산물: 체인별 분석 아카이브 — 차기 저술 소재로 축적
- 설계 철학: **근거 없는 숫자는 표시하지 않음.** 모든 점수는 분해 가능, 모든 엣지는 출처로 역추적 가능 (여신 심사 감각)

## 2. 기반 데이터 전략 (핵심 결정)
- 보유 리서치 자산 2종의 **역할 분리**:
  - **A. 최근 산업·기업 분석 자료 (홈페이지 리서치 포함)** → 현재 그래프 구축 + 스코어 캘리브레이션의 기반. 이미 '불가결 노드' 렌즈로 분석된 결과물 = 정답지(ground truth)로 활용 가능
  - **B. 책 집필 리서치** → 백테스트 케이스 라이브러리 (v1.2). 과거 '불가결→붕괴/성공' 사례로 프레임워크의 시간축 예측력 검증. 공급망 데이터는 유통기한이 짧아 현재 스냅샷보다 역사 검증에서 가치가 큼
- MVP 체인 #1: **HBM 체인** (제안) — 범위가 좁고 깊음 / 국내 공시(DART) 데이터 강함 / 본인이 병목의 답을 이미 앎. 대안 교체 허용
- 체인 #2 (일반화 테스트): AI 전력 체인
- 시드 인제스트 경로: `/data/seed/recent/`(A 자산), `/data/seed/book/`(B 자산) — 파일(메모·PDF·MD)·URL 목록 모두 허용. 태그 분리 저장 (B는 백테스트 전용)

## 3. 데이터 모델 (그래프 스키마)

### 3.1 2층 구조
- **Layer 1 — 기능 노드(Function)**: 공정·기술 단계 (예: "TC 본딩", "HBM용 언더필 소재", "EUV 노광"). 병목은 기능 수준에서 발생
- **Layer 2 — 기업 노드(Company)**: 기능을 수행하는 기업. 기능 노드에 매핑 (N:N). 투자는 기업 수준에서 실행
- 스코어링은 기능 먼저 → 기능 점수를 소속 기업에 배분(점유율 가중)

### 3.2 스키마 (JSON)
```json
{
  "functions": [
    {"id": "fn_tc_bond", "name": "TC 본딩", "chain": "hbm", "stage": "후공정"}
  ],
  "companies": [
    {"id": "co_xxx", "name": "OO반도체", "ticker": "000000.KS", "functions": [{"fn": "fn_tc_bond", "share": 0.6, "evidence": ["url"], "confidence": 0.8}]}
  ],
  "edges": [
    {
      "from": "co_xxx", "to": "co_yyy", "type": "supply | tech_dependency | qualification",
      "share": 0.35, "evidence": ["https://dart..."], "confidence": 0.7,
      "asof": "2026-06", "substitutable": false, "note": "퀄 기간 18개월"
    }
  ]
}
```
- **모든 엣지에 evidence + confidence 필수.** confidence < 0.5는 그래프에서 점선 표시
- 저장: JSON/parquet 파일 기반 (MVP), 스냅샷 날짜별 보관 (`graph/hbm/2026-07.json`) — 추후 모멘텀 계산의 원천

## 4. 스코어링 엔진 (5축, 0~100)
- **S1 구조 (0~25)**: betweenness centrality 백분위(체인 내) + 단절점(articulation point) 보너스. NetworkX 표준 함수 사용
- **S2 대체 장벽 (0~25)**: 기능 내 실질 경쟁사 수(역수) / 인증·퀄 전환 기간(년) / 특허 인용 밀도
- **S3 경제성 (0~20)**: 비대칭 점수(다운스트림 원가에서 차지하는 비중은 낮은데 공정 치명도는 높음) + GPM의 동종 대비 스프레드
- **S4 수요 내구성 (0~15)**: 최종수요 성장률, 사이클 민감도(감점형)
- **S5 감점 (0~−25)**: 고객 집중도(최대 고객 매출 비중) / 고객사 내재화 시그널(관련 채용공고·특허 출원 방향) / 대체 기술 경로의 성숙도
- 합성: 가중합 → 0~100 클립. **가중치는 `config/weights.yaml`로 외부화** (본인 튜닝 전제, 코드 하드코딩 금지)
- **RaRR (제거 시 증발 매출)**: 노드 제거 → 대체 엣지(substitutable=true) 없는 다운스트림 도달 불가 매출 합계. 매출 데이터 없으면 노드 수 기반 근사 허용(MVP), 근사 여부 표기
- 캘리브레이션 원칙: 시드 체인에서 본인이 아는 병목이 상위에 오도록 가중치 조정 — §8 정답지 루프에서 수행

## 5. 데이터 소스·수집
- 우선순위 순:
  1. **수동 입력 (MVP 필수)**: CSV/폼으로 본인 리서치 직접 입력 — 자동화 만능주의 배제, 초기 그래프의 뼈대
  2. **DART**: 사업보고서 '사업의 내용'·주요 매출처·원재료 매입처 (기존 DART 파서 코드 재활용 검토)
  3. EDGAR 10-K: 10% 이상 고객 공시
  4. 특허: KIPRIS·Google Patents 인용 (기술 의존성 프록시)
  5. 무역 통계: HS코드 수출입 (점유율 프록시)
- **LLM 추출 파이프라인 (2-pass)**:
  - Pass 1: 문서 → 트리플 JSON 추출. 규칙: "문서에 명시된 것만, 추론 금지, 원문 인용구 포함, confidence 자기평가"
  - Pass 2: 검증 — 인용구가 원문에 실제 존재하는지 문자열 대조 (환각 방어). 불일치 시 해당 트리플 폐기
- 밸류에이션 축: MVP는 수동 CSV (ticker, 시총, PER, EV/EBITDA). 자동 연동은 v2

## 6. 화면 (MVP 3장 고정)
- **①그래프 뷰**: 노드 크기=스코어, 색=Layer 구분, confidence 낮은 엣지 점선. **제거 시뮬레이션 버튼**: 노드 클릭 → 끊기는 경로 하이라이트 + RaRR 숫자 표시 (데모·콘텐츠용 킬러 기능)
- **②스코어보드**: 정렬 테이블. 총점 + 5축 분해 컬럼, 셀 클릭 → 근거(출처 링크) 드릴다운
- **③2×2 매트릭스**: X=밸류에이션, Y=불가결성 스코어. "싸고 불가결" 사분면 강조, "비싸고 대체가능" 사분면은 역방향 후보 표시
- 그 외 화면 금지 (스코프 방어)

## 7. 기술 스택
- 제안: Python 3.12 (NetworkX, pandas) — 파이프라인·스코어링 / FastAPI — JSON 서빙 / React + Cytoscape.js — 뷰
- 단순화 대안 허용: 전체 Streamlit 구성 (그래프는 st-link-analysis 등) — Claude Code 판단, `DECISIONS.md`에 근거 기록
- LLM: Anthropic API (추출·리포트 생성). API 키 `.env` 서버 사이드
- 재현성: 모든 스코어 산출은 `graph 스냅샷 + weights.yaml` 두 입력만으로 결정적(deterministic) 재계산 가능해야 함

## 8. 개발 계획 — 루프 기반

> 상세 루프 정의·연동 흐름·실행 프롬프트는 **`LOOP_PLAN.md`** 참조.
> 본 섹션은 요약. 루프 간 충돌 시 LOOP_PLAN.md가 우선.

### 8.1 Phase 구성 + 루프 매핑

| Phase | 내용 | 내장 루프 | Gate 기준 |
|-------|------|----------|-----------|
| 0 | 스키마·저장 | L0 스키마 스트레스 | 왕복 + 엣지케이스 전수 통과 |
| 1 | 시드 인제스트 | L1 추출 품질 → L2 커버리지 갭 → L3 무결성 | Pass 2 ≥ 85%, GT 8/10+, 고립 노드 0 |
| 2 | 스코어링 v1 | L4 정답지 캘리브레이션 | Recall@20% ≥ 0.8, LOO 상위 30% |
| 2-3 | 품질·강건성 | L5 데이터 품질 ↔ L6 강건성 | 불량률 < 10%, τ ≥ 0.8 |
| 3 | 화면 3장 | L7 시각화 QA | 체크리스트 전항목 ✓ |
| 4 | 자동 수집 (DART) | L1 재실행 (신규 소스) | 신규 엣지 2-pass 통과 |

### 8.2 루프 간 연동 (핵심)

```
L1 추출 품질 ←── 프롬프트 피드백 ──→ L5 데이터 품질
     │                                    │
     ↓                                    ↓
L2 커버리지 갭 ──→ L3 그래프 무결성 ──→ L4 정답지 캘리브
     │                                    │
     └──── CSV 수동 보강 ←────────────────┘
                                          │
                                     L6 강건성
```

- L5에서 체계적 오류 패턴 → L1 프롬프트 수정으로 **역류**
- L4에서 엣지 누락 진단 → L3로 **회귀**
- 루프는 독립이 아닌 **상호 피드백** 구조

### 8.3 각 루프 요약

**L0 스키마 스트레스** (Phase 0, max 3cy): 왕복 + 엣지케이스 (빈 그래프, alias 양방향, 한글 ID, 결정론적 출력) → 전수 통과

**L1 추출 품질** (Phase 1, max 3cy): LLM 추출 → Pass 2 검증 → 폐기 원인 분류 (환각/오인용/범위초과/형식오류) → 프롬프트 규칙 추가 → 폐기율 높은 파일만 재추출. 종료: 전체 ≥ 85% AND 파일별 ≥ 70%

**L2 커버리지 갭** (Phase 1, max 2cy): ground_truth 10개 노드 존재 확인 → 누락 원인 진단 (소스 부재/추출 실패/Pass 2 폐기) → L1 재실행 or CSV 보강. 종료: 8/10+

**L3 그래프 무결성** (Phase 1→2 브릿지, max 2cy): 고립 노드, 기능 미매핑, 댕글링 참조, 연결 컴포넌트 검사 → 자동/수동 수정. 종료: 전수 통과

**L4 정답지 캘리브레이션** (Phase 2, max 5cy): 스코어 → Recall@20% → 미달 원인 이분법 (가중치 vs 엣지 누락) → 수정 + LOO 교차 검증. 종료: Recall ≥ 0.8 + LOO 상위 30%, 또는 2cy 연속 정체

**L5 데이터 품질** (Phase 2-3, max 3cy): 엣지 20개 샘플 → evidence 원문 대조 → 불량 분류 + 수정/폐기. 체계적 패턴 → L1 프롬프트 역류. 종료: 불량률 < 10%

**L6 강건성** (Phase 2-3, max 3cy): confidence 하위 엣지 단계적 제거 → 랭킹 유지율 (Kendall τ) → 저신뢰 의존 노드 보강. 종료: 하위 20% 제거 시 τ ≥ 0.8

**L7 시각화 QA** (Phase 3, max 3cy): 렌더링 → 8항목 체크리스트 (노드 크기, 점선, 제거 시뮬, 드릴다운 등) → 미통과 수정 → 재렌더링. 종료: 전항목 ✓

## 9. Claude Code 실행 프롬프트

> 프롬프트 P-0 ~ P-7의 전문은 **`LOOP_PLAN.md`** 하단 참조.
> 아래는 실행 순서와 의존 관계 요약.

```
P-0 (Phase 0 + L0) → P-1 (L1 추출) → P-2 (L2 커버리지) → P-3 (L3 무결성)
     │                                                          │
     └────── Phase 0-1 완료 ────────────────────────────────────┘
                                                                │
P-4 (Phase 2 + L4 캘리브) → P-5 (L5 품질) → P-6 (L6 강건성)
     │                                          │
     └────── Phase 2 완료 ──────────────────────┘
                                                │
P-7 (Phase 3 + L7 QA) → 최종 완료
```

- 각 프롬프트는 이전 프롬프트의 산출물이 존재하는 상태에서 실행
- 루프 간 역류(L5→L1 등) 발생 시 해당 프롬프트가 자동으로 지시
- 프롬프트 하나 = Claude Code 세션 하나 (컨텍스트 분리)

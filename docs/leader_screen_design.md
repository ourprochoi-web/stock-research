# 주도주 스크린 v1 — 설계 (2026-09-15 · 성상현 격자를 빌려 우리 데이터로 다시 짬)

**한 줄**: 판단(브레인)은 「왜 오르나」를 답하고, 스크린은 「지금 돈이 어디로 가고 있나」를 답한다. 둘은 다른 질문이라 섞지 않는다 — 스크린은 후보를 좁힐 뿐(§C1 grep과 같은 지위) 판단하지 않는다.

## 1. 유니버스 = 추적 종목 188(KR 102 · US 86)
새 유니버스를 만들지 않는다. 추적 목록 자체가 「아카이브가 판단을 갖거나 가지려는 종목」이고(`update_prices.py` TICKERS·WATCH·WATCH_US), 거기 없는 종목은 판단이 없으니 스크린에 올라도 살 근거가 없다. 유니버스를 넓히는 방법은 판단을 세우는 것뿐이다.

## 3. 격자와 게이트 (성상현에서 빌린 핵심)
- **A** G≥50 & P≥50 → 보유·주도주 후보
- **B** G≥50 & P<50 → **게이트**: ΔOPM ≥ 0 & 분기 매출 YoY > 0 이면 「눌림목(이익 유지)」, 아니면 「탈락 후보(이익 하향)」
- **C** G<50 & P≥50 → 사이클·테마 점검(이익 없이 가격만)
- **D** 나머지 → 제외

게이트가 우리 §J(판정 이벤트 = 틀렸음을 빨리 아는 장치)와 같은 구조다. 09-10 VCP 백테스트가 실패한 이유(가격만 봄 · 승률 40% · 상위 5개가 평균을 만듦)를 메우는 세 가지: 이익 게이트 · 균등비중 · 섹터 캡.

## 4. 포트 구성 규칙(제안 · 집행은 사용자 §J3)
- 시장별 상위 N(기본 10) **균등비중** — 시총가중은 지수다.
- **섹터 캡 3/10** — 같은 층(메모리·광·전력·사이버 …)이 4개째면 다음 순위로 내린다. v1은 섹터 태그가 없어 수동 확인(entities.layer 49사만 있음 → 확장 항목).
- **월 1회** 재실행(성상현의 리밸런싱 주기). 스코어 유지면 종목 불변. A→B 이동은 routing에 남긴다.
- **판단 보유 여부**를 표시 — 스크린 상위인데 판단 0편이면 그게 다음 페이퍼 대상이다(커버리지 지도).
